# Kimi Radar

面向 Kimi 增长 / 内容运营的本地工具：从 X 用户信号中发现值得验证的选题，生成英文文案与 Kimi 工作流，保存实测记录，并对比品牌的公开内容表现。

## 启动

```bash
python3 kimi-radar/server.py --port 3477
```

打开 <http://127.0.0.1:3477>。Python 标准库，无额外依赖。HTML 界面由本地服务提供，不是直接双击文件运行。

## 文档

- `BUILD.md`：为什么做、面向谁、优化目标与范围。
- `FRONTEND_HANDOFF.md`：前端接手必读，包含用户确认的要求、API 契约、字段、页面职责和边界。
- `VALIDATION.md`：已实际验证的功能与剩余限制。

## 私有配置

复制 `.env.example` 到 `.env`，填写 TwitterAPI.io 和 Moonshot API key。密钥只在服务端读取，不需要重启即可刷新配置。

本次提供的 Kimi key 已确认适用于 `https://api.moonshot.cn/v1`，私有 `.env` 已配置正确地址。国际平台对应 `https://api.moonshot.ai/v1`，两者密钥不可假定通用。

原始 X Tracker 的代码、飞书集成和凭据未被修改。新应用不会从父目录读取密钥。

## 使用

1. 在「信号来源」查看账号与关键词，设置采集窗口，点击真实采集。查询自带 `since:` / `until:` 时按查询本身的范围采集；否则使用采集窗口（默认 8 天）。「表现对标」固定使用 24 小时至 8 天，不随采集窗口变化。
2. 在「机会雷达」读原文，分开看「社交潜力」和「证据强度」两个轴，选择值得测试的用例创意。两轴均为纯计算，不由模型打分；社交潜力是本批采集内的排名，跨批次不可比。
3. 创建实验，编辑英文文案和提示词。
4. 在 Kimi 产品中手动实测，记录检查结果与下一步。
5. 保存 / 导出实验，使用「表现对标」辅助下次内容决策。

「演示样本」的帖子与指标均为合成，不能作为真实研究结果。真实数据和样本、已保存实验的证据快照保持分离。界面不自动发布到 X。
